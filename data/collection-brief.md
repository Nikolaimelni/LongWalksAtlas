# Бриф: сбор пеших маршрутов для Long Walks Atlas

Нужно собрать известные многодневные пешие маршруты мира и вернуть один JSON-файл по
формату ниже. Это справочник: не этапы и ночёвки, а факты о маршруте целиком, линия
из OpenStreetMap и ссылка на официальный источник.

## Какие маршруты брать

- Многодневные пешие маршруты: от 3 дней пути или от ~50 км.
- Маршрут именованный и маркированный (или официально описанный): паломнические пути,
  исторические, прибрежные, горные, национальные и трансграничные тропы, E-пути.
- У маршрута есть официальный или авторитетный источник (управляющая организация,
  туристическое ведомство страны, ассоциация тропы). Без такого источника не брать.
- Маршрут есть в OpenStreetMap как отношение (relation) с `route=hiking` или
  `route=foot`. Если его там нет, всё равно включить, но поставить `osm.relationIds: []`
  и объяснить в `notes`.
- Варианты одного пути (например, ветки Камино) это отдельные записи, если у них свои
  названия и свои официальные описания.

## Поля каждой записи

Обязательные помечены *. Если факт не удалось подтвердить источником, ставь `null`,
а не догадку.

| Поле | Формат | Что это |
| --- | --- | --- |
| `slug`* | `kebab-case`, латиница | Уникальный id: `camino-frances`, `west-highland-way` |
| `nameOriginal`* | строка | Название на языке страны: `Caminho Português`, `Likya Yolu` |
| `nameEn`* | строка | Общепринятое английское название |
| `type`* | одно из: `pilgrimage`, `historic`, `coastal`, `mountain`, `e-path` | Тип. Если ни один не подходит, ближайший и предложение в `suggestedType` |
| `suggestedType` | строка или `null` | Свой тип, если наши пять не подходят (например `desert`, `forest`) |
| `region`* | одно из: `europe`, `middle-east-caucasus`, `asia`, `americas`, `africa`, `oceania` | Регион |
| `countries`* | массив ISO 3166-1 alpha-2, заглавными | `["PT", "ES"]` |
| `start`* | `{ "name": "...", "coords": [lng, lat] }` | Начало. **Порядок: долгота, потом широта** |
| `end`* | то же | Конец. Для кольца совпадает со `start` |
| `lengthKm` | число или `null` | Официальная длина основного маршрута, км |
| `days` | `{ "min": n, "max": n }` или `null` | Дней пешком по официальному источнику |
| `bestSeason` | массив из `jan` … `dec` | Лучшие месяцы по официальному источнику |
| `badges` | массив из `coe-cultural-route`, `unesco` | Только если это подтверждено: культурный маршрут Совета Европы, объект ЮНЕСКО |
| `officialUrl`* | https-ссылка | Официальный сайт маршрута или ведомства |
| `sources`* | массив https-ссылок | Страницы, на которых проверены длина, дни, сезон, начало и конец. Минимум одна |
| `osm.relationIds`* | массив чисел | ID отношений OSM. Если маршрут разбит на части, все части по порядку |
| `osm.notes` | строка или `null` | Что известно о линии: неполная, есть варианты, в отношении лишние ветки |
| `photo` | `{ "commons": "File:....jpg" }` или `null` | Файл с Wikimedia Commons, снятый на этом маршруте, горизонтальный, лицензия CC BY, CC BY-SA, CC0 или public domain (не NC и не ND) |
| `wikidata` | `Q…` или `null` | Элемент маршрута на Wikidata, например `Q1731039` у Ликийской тропы. Часто стоит в теге `wikidata` отношения OSM; проверь, что это весь маршрут, а не его участок |
| `summaryEn`* | 1–2 предложения, до 300 знаков | Что это за маршрут, откуда и куда. Своими словами |
| `storyEn`* | 2–4 абзаца, Markdown | История и характер маршрута. Своими словами, без копирования источников; ссылки в тексте допустимы |
| `confidence`* | `high`, `medium`, `low` | Насколько уверен в цифрах и линии |
| `notes` | строка или `null` | Всё, что стоит знать: расхождения источников, спорные цифры |
| `checkedAt`* | `YYYY-MM-DD` | Дата проверки |

## Правила проверки

1. Цифры (длина, дни, сезон) только из открытых страниц, перечисленных в `sources`.
   Сниппет поисковика не источник. Если источники расходятся, бери официальный, а
   расхождение опиши в `notes`.
2. ID отношения OSM проверяй открытием `https://www.openstreetmap.org/relation/<id>`:
   название и район должны совпадать. Для маршрута из частей (страны, этапы) лучше
   одно суперотношение, если оно есть.
3. Координаты начала и конца берутся из реального места старта (собор, вокзал, площадь),
   с точностью 4 знака. Ещё раз: `[долгота, широта]`.
4. Тексты `summaryEn` и `storyEn` должны быть своими формулировками. Никаких
   скопированных абзацев из Википедии или официальных сайтов.
5. Фото только с Commons, только подходящих лицензий, только с этого маршрута.
6. `slug` уникальны во всём файле.

## Формат ответа

Один JSON-файл: объект с полем `trails` (массив записей) и `generatedAt`.

```json
{
  "generatedAt": "2026-10-20",
  "trails": [
    {
      "slug": "west-highland-way",
      "nameOriginal": "West Highland Way",
      "nameEn": "West Highland Way",
      "type": "mountain",
      "suggestedType": null,
      "region": "europe",
      "countries": ["GB"],
      "start": { "name": "Milngavie", "coords": [-4.3171, 55.9426] },
      "end": { "name": "Fort William", "coords": [-5.1060, 56.8198] },
      "lengthKm": 154,
      "days": { "min": 6, "max": 8 },
      "bestSeason": ["may", "jun", "sep"],
      "badges": [],
      "officialUrl": "https://www.westhighlandway.org/",
      "sources": ["https://www.westhighlandway.org/"],
      "osm": { "relationIds": [0], "notes": null },
      "photo": { "commons": "File:Example.jpg" },
      "wikidata": "Q123456",
      "summaryEn": "One or two sentences in your own words.",
      "storyEn": "Two to four paragraphs in your own words.",
      "confidence": "high",
      "notes": null,
      "checkedAt": "2026-10-20"
    }
  ]
}
```

Цифры, ID и файл фото в примере условные: показан только формат.
